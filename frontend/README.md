# EKT AI Assistant — frontend

Автор UI: Moveath. Адаптивный интерфейс на HTML/CSS/JavaScript без зависимостей в браузере.

Основной вариант — один origin: из корня проекта запустить установленный FastAPI backend:

```powershell
python -m uvicorn main:app --host 127.0.0.1 --port 8000
```

Открыть http://127.0.0.1:8000. Существующий `StaticFiles` раздаёт чат и `/cart/` (переход с `/cart` автоматически добавляет завершающий слеш). Корзина читает данные с `GET /api/cart` в той же cookie-сессии.

Для отдельного локального frontend-сервера требуется Node.js 20+:

```powershell
cd frontend
npm start
```

Открыть http://localhost:5173. В отдельном терминале запустить существующий FastAPI backend на порту 8000 согласно его настройкам. UI работает и без backend, но запросы показывают сообщение о недоступности; вымышленные товары не отображаются.

`server.mjs` раздаёт только явно разрешённые файлы frontend и проксирует `POST /api/chat`, `GET /api/cart` и `GET /health`. Для API передаются `Cookie` и отдельные `Set-Cookie`; содержимое cookie не читается JavaScript и не логируется. По умолчанию `BACKEND_URL=http://127.0.0.1:8000`; переменную можно задать в терминале. Секреты frontend не нужны. Локальный сервер слушает только loopback. Для общего доступа предпочтителен один origin через FastAPI; `localhost` и `127.0.0.1` не разделяют cookie.

Поддержаны история последних 12 сообщений, четыре быстрых запроса, форматирование длинных ответов, карточки товаров, окно подробностей, характеристики без JSON, загрузка/ожидание ответа, пустая выдача, ошибки и повтор запроса. Черновик сохраняется при ожидании ответа. Enter отправляет, Shift+Enter переносит строку. Новый диалог очищает историю чата, но не серверную корзину.

Карточки различают доступный, отсутствующий и неизвестный остаток, отмечают возможные аналоги и необходимость проверки совместимости. Отсутствующая единица отображается обобщённо: «ед.» / «бірл.» / «units»; исходный товар не меняется. Приоритет артикула — `product.article`, затем характеристика «Артикул», затем честно обозначенный внутренний код. Показываются фото `image`, ссылка `url` на EKT, сертификат и полезные характеристики. Служебные поля `BRAND_PRIORITY`, `CML2_*`, `IMYAKARTINKI`, `NOVINKA`, `SPETSPREDLOZHENIE`, `RECOMMEND`, `KRATNOST_*` скрыты. В подробностях отображаются склады из `stores` с положительным числовым `quantity`. Отбор продаваемых складов выполняет backend.

Кнопка «Выбрать для корзины» доступна при конечном числовом `stock > 0`, независимо от единицы. Открытие и отмена подтверждения ничего не добавляют. Только явное подтверждение передаёт `confirm_cart: [{product_id, quantity}]` в существующий API. Положительный числовой `min_order` задаёт `min`, `step` и исходное количество; несоблюдение кратности показывает ошибку и блокирует подтверждение. Значение не округляется автоматически. Без `min_order` сохраняется прежняя поддержка дробных положительных количеств. Остаток и лимит 1 000 000 проверяются отдельно. Backend обязан повторить проверки.

`/cart` отображает серверные позиции, количество, цену, сумму строки, остаток, ссылки EKT и итог из `GET /api/cart`. Счётчик в шапке — число позиций из того же ответа; при недоступности API он скрывается, а не подменяется нулём. Корзина не сохраняется в `localStorage`. Есть загрузка, пустое состояние, ошибка и повтор. Новое сообщение закрывает старое предложение подтверждения; новый чат не очищает корзину.

Успех показывается только при `cart.status="confirmed"` и `cart.added_to_cart=true` после явного подтверждения; затем счётчик обновляется запросом к серверу. Абсолютный безопасный `cart.cart_url` используется для перехода; при отсутствии корректного URL доступна локальная `/cart`. При `added_to_cart=false` интерфейс прямо сообщает, что добавление не подтверждено. Текущий backend ещё не содержит `/api/cart`, `min_order` и настоящего добавления: это внешняя зависимость, описанная в [BACKEND_CONTRACT.md](BACKEND_CONTRACT.md). Бизнес-логика backend не менялась; при объединении исправлена синтаксическая опечатка в последней строке `main.py`.

Запрос «Условия доставки» отправляется тому же ассистенту. В текущем API нет отдельного источника условий доставки: UI не подставляет вымышленные сроки или тарифы. Индикатор «Сервер на связи» означает ответ `/health`, а не гарантию доступности каталога и AI. API не потоковый; индикатор подготовки ответа означает ожидание, а не получение токенов.

Проверки без установки зависимостей:

```powershell
npm run check
npm test
```

Проверяемый сценарий: поиск → фото/артикул/подробности/остатки по городам → выбор товара без `unit` → отмена без запроса → количество с `min_order` → явное подтверждение → сообщение согласно `added_to_cart` → серверная корзина. Проверить пустую корзину, 404/сбой/повтор, RU/KZ/EN и ширину 360 px. Изолированные тесты используют тестовые ответы API и не доказывают готовность серверной реализации.

Адаптивная сетка перестраивает карточки в одну колонку на телефоне. Модальные окна используют native `dialog` с управлением фокусом и Escape; интерактивные элементы имеют видимый фокус, а анимации отключаются при `prefers-reduced-motion`.

## Языки интерфейса

RU / ҚАЗ / EN переключаются через `#language` без перезагрузки. По умолчанию — русский. Выбор сохраняется в `localStorage` под ключом `ekt-language`; при недоступном хранилище переключение продолжает работать в памяти вкладки. Для казахского HTML использует стандартный языковой код `kk`, а согласованный будущий API-параметр — `kz`.

- `locales.js` — единый словарь со смысловыми ключами и одинаковым набором RU/KZ/EN.
- `i18n.js` — подстановка текста/атрибутов, сохранение языка, обновление уже созданных карточек и окон. Ввод, количество, фокус и история не сбрасываются.
- `ui-model.js` — локализованные служебные подписи и форматирование чисел; исходные названия, артикулы, модели, единицы и текстовые характеристики каталога не переводятся.
- `api.js` — совместимый построитель запроса. При обычной работе отправляет только `query`, `history`, `confirm_cart`.

Ответы AI, прежние сообщения и произвольный текст каталога остаются в исходном виде. Известные коды ошибок и два фиксированных предупреждения backend переводятся по словарю, неизвестные ошибки показывают понятный локализованный fallback. Неизвестные текстовые предупреждения API не переводятся автоматически. Фотографии товаров отсутствуют в текущем API-контракте, поэтому frontend не придумывает изображения.

### Минимальное изменение backend для языка AI (ещё не выполнено)

Текущий `ChatRequest` использует `extra="forbid"` и не принимает `language`. Чтобы подключить язык ответов:

1. Команде backend нужно добавить `language: Literal["ru", "kz", "en"] = "ru"` в `ChatRequest`.
2. Передать выбранный язык в контекст модели и потребовать ответ/пояснения на нём, сохраняя имена, модели и характеристики товаров. Также локализовать шаблонные серверные ответы подтверждения или отдавать их коды для frontend.
3. После согласования API включить `backendCapabilities.language` в `api.js`. Тогда запрос добавит поле `language`. Текущий контракт покрыт тестом и по умолчанию не меняется.

Backend и `.env` для этой задачи не редактировались. Выбор EN/KZ сейчас меняет язык интерфейса и текст готовых вопросов, но не гарантирует язык ответа AI.

## Адаптивность и проверки

Высота приложения определяется доступным viewport, без фиксированной минимальной высоты чата. `viewport.js` учитывает `visualViewport`, экранную клавиатуру и поворот устройства; safe-area отступы заданы в CSS. На мобильном сокращена второстепенная навигация, основные действия остаются доступными. Длинные сообщения, характеристики и модальные окна прокручиваются внутри своих областей.

Проверки `npm test` включают полноту переводов и placeholders, сохранность исходных значений, безопасность ссылок и отсутствие неподдерживаемого `language` в запросе. Браузерные проверки используют отдельные тестовые ответы API, а не демонстрационные данные в приложении. Матрица: 1920×1080, 1440×900, 1366×768, 1024×768, 768×1024, 430×932, 390×844, 375×812, 360×800 и 320×740 для всех трёх языков. Дополнительно проверяются смена языка при загрузке/ошибке/открытом окне, сохранение после reload, клавиатура, длинные ответы и названия, подтверждение и отсутствие ложного успеха корзины.
