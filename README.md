# ⚡ EKT.kz AI Assistant — Умный ИИ-консультант для интернет-магазина электротехники

> **Хакатон ekt.kz | Трек «Торговля»**  
> Интеллектуальный AI-ассистент с поиском по каталогу товаров, автоматическим подбором аналогов и защищённым механизмом добавления в корзину по правилу Must Have.

---

## 🎯 1. Проблема

Интернет-магазин электротехники **ekt.kz (ГК Электрокомплект)** ежедневно обрабатывает тысячи обращений клиентов. Анализ процессов выявил следующие проблемы:

- **Перегрузка менеджеров:** До 70% времени специалистов уходит на однотипные справочные вопросы (*«Есть ли кабель ВВГнг 3х2.5?», «Чем заменить автоматический выключатель на 16А?»*).
- **Длительное ожидание клиентов:** В пиковые часы клиенты ждут ответа менеджера, из-за чего снижается конверсия и падают продажи.
- **Сложность подбора:** Электротехнический каталог содержит тысячи узкоспециализированных параметров (сечения, IP-защита, ампераж, бренды), в которых покупателю трудно сориентироваться без консультации.
- **Риск случайных покупок:** При автокликах или ошибочных подсказках клиенты получают не тот товар, что влечет за собой возвраты.

---

## 💡 2. Наше решение

Мы разработали **умного ИИ-консультанта**, встроенного в веб-сайт ekt.kz. Бот берет на себя подбор электротехники, поиск альтернатив и помощь в оформлении заказа.

### ✨ Ключевые возможности:
1. **Точный поиск по каталогу ekt.kz:** Понимание профессиональных терминов, сечений, моделей и артикулов продукции.
2. **Умный подбор аналогов:** При отсутствии нужного товара бот мгновенно находит 100% совместимые альтернативы по техническим параметрам и цене.
3. **Безопасная корзина (Правило Must Have):** Товар добавляется в корзину **строго после явного и однозначного подтверждения клиента** (например, *"Да, добавь в корзину"*). Случайные действия полностью исключены.
4. **Интеграция с API ekt.kz:** Получение актуальных цен и остатков на складах в режиме реального времени.

## 🏗️ 3. Архитектура и Технологический Стек

```
┌──────────────────┐       ┌──────────────────────┐       ┌─────────────────────┐
│    Next.js UI    │ ────> │ FastAPI Backend (Py) │ ────> │   OpenAI GPT-4o     │
│   (Chat Widget)  │ <──── │  (REST / Async API)  │ <──── │  (Function Calling) │
└──────────────────┘       └──────────────────────┘       └─────────────────────┘
                                      │
                                      ▼
                           ┌──────────────────────┐
                           │   Каталог EKT.kz     │
                           │  (REST API / MySQL)  │
                           └──────────────────────┘
```

- **Backend:** Python 3.11+, FastAPI, Pydantic, Uvicorn
- **AI Core:** OpenAI GPT-4o + **Function Calling (Tools)** для строгого контроля бизнес-логики и выполнения правил корзины
- **Frontend:** Next.js 14, React, TailwindCSS, Lucide Icons
- **Database / Search:** PostgreSQL / In-Memory Index для быстрого поиска по каталогу ekt.kz

## 🚀 4. Инструкция по запуску для Жюри

### Предварительные требования
- Python 3.10+
- Node.js 18+
- Ключ OpenAI API (`OPENAI_API_KEY`)

### Шаг 1. Клонирование репозитория
```bash
git clone https://github.com/your-team/ekt-ai-assistant.git
cd ekt-ai-assistant
```

### Шаг 2. Запуск Бэкенда (FastAPI)
```bash
cd backend

# Создание и активация виртуального окружения
python -m venv venv
source venv/bin/activate  # Для Windows: venv\Scripts\activate

# Установка зависимостей
pip install -r requirements.txt

# Создание файла конфигурации
cp .env.example .env
# Добавьте ваш OPENAI_API_KEY в файл .env

# Запуск сервера
uvicorn main:app --reload --port 8000
```
*Интерактивная документация Swagger доступна по адресу:* `http://localhost:8000/docs`

### Шаг 3. Запуск Фронтенда (Next.js)
```bash
cd ../frontend

# Установка зависимостей
npm install

# Запуск в режиме разработки
npm run dev
```
*Чат-интерфейс доступен по адресу:* `http://localhost:3000`

## 📊 7. Аналитика продукта и KPI

### 7.1. Что именно автоматизирует ассистент

По структуре публичного каталога EKT пользователь работает как минимум с **11 крупными группами товаров**: кабель/провод, светильники/лампы, низковольтная аппаратура, кабеленесущие системы, изделия для монтажа и инструмент, прочее оборудование, шкафы/щиты, розетки/выключатели/коробки, автоматизация, видеонаблюдение/СКУД/сигнализация и инструмент/КИП. Каталог также использует фильтрацию по техническим параметрам, например по току, длине, материалу и другим характеристикам. [EKT.kz](https://ekt.kz/catalog/) 

Это делает обычный поиск по названию недостаточным: ассистент должен учитывать **модель, технические параметры, совместимость, наличие и цену**.

### 7.2. Основные продуктовые метрики

| Метрика | Что измеряем | Целевой KPI пилота |
|---|---|---:|
| Search Success Rate | Доля запросов, где найден релевантный товар | ≥ 90% |
| Top-3 Recall | Нужный товар/аналог попал в первые 3 результата | ≥ 90% |
| Compatibility Accuracy | Корректность подбора аналога по обязательным параметрам | ≥ 95% |
| Cart Confirmation Compliance | Доля добавлений, выполненных только после явного подтверждения | 100% |
| Tool Success Rate | Успешность вызовов поиска/корзины/API | ≥ 98% |
| Response Latency | Время ответа ассистента | p95 ≤ 3 сек* |
| Hallucination Rate | Ответы с неподтверждёнными товарными данными | ≤ 1% |
| Human Escalation Rate | Доля запросов, переданных менеджеру | отслеживать по причинам |
| Session Conversion | Доля консультаций, завершившихся целевым действием | сравнивать с baseline |

\* Целевой порог зависит от инфраструктуры, API EKT и модели; в MVP это именно измеряемая цель, а не заявленный факт.

### 7.3. Сценарная оценка экономического эффекта

Ниже — **модель**, а не фактическая статистика EKT. Она нужна для расчёта потенциального эффекта после подключения реальных данных.

Предположим:

- 1 000 консультаций в месяц;
- 70% запросов относятся к типовым справочным задачам;
- 80% таких типовых задач способен закрывать AI без участия менеджера;
- среднее время менеджера на одну такую консультацию — 5 минут.

Тогда:

```text
1 000 × 70% = 700 типовых запросов
700 × 80% = 560 запросов, потенциально обработанных AI
560 × 5 мин = 2 800 мин
2 800 / 60 ≈ 46,7 часа менеджера в месяц
```

При другом среднем времени на консультацию:

| Среднее время менеджера | Высвобождаемая ёмкость при 560 AI-сценариях |
|---:|---:|
| 3 мин | 28 ч/мес |
| 5 мин | 46,7 ч/мес |
| 8 мин | 74,7 ч/мес |
| 10 мин | 93,3 ч/мес |

Таким образом, фактический эффект можно рассчитывать без догадок после получения трёх данных из CRM/helpdesk: **число обращений → доля типовых → среднее время обработки**.

### 7.4. Модель влияния на конверсию

Показатель `+25% к конверсии` из предыдущего раздела следует воспринимать как **целевой сценарий для A/B-теста**, а не как уже доказанный результат.

Пример:

```text
Baseline: 1 000 квалифицированных сессий
Конверсия без AI: 2,0%
Заказов: 1 000 × 2,0% = 20

Целевой рост: +25% относительно baseline
Новая конверсия: 2,5%
Заказов: 1 000 × 2,5% = 25

Разница: +5 заказов на 1 000 квалифицированных сессий
```

Фактический KPI предлагается определять экспериментом:

**A/B тест**
- A — стандартный поиск/консультация;
- B — поиск + AI-подбор + аналоги + controlled cart;
- сравниваются conversion rate, add-to-cart rate, средний чек, время до товара и доля обращений к менеджеру.

### 7.5. Почему автоматизация консультирования экономически оправдана

McKinsey оценивал потенциал применения generative AI в customer care в диапазоне **30–45% текущих затрат функции** за счёт роста производительности. Это отраслевой ориентир, а не прогноз именно для EKT. citeturn781833search0

В отдельном кейсе, описанном McKinsey, после внедрения generative-AI чатбота нагрузка на customer service снизилась на **30%**, а сам бот решил более **40% обращений**, с которыми взаимодействовал. Это также внешний кейс и используется только как benchmark для постановки KPI. citeturn781833search8

## 🧪 8. Как будем измерять качество AI

Для продукта с техническими товарами одной оценки «ответ выглядит правильно» недостаточно. Поэтому вводим тестовую выборку из реальных или обезличенных запросов и считаем:

### Retrieval / Search

```text
Top-1 Accuracy = правильный товар в позиции №1 / все тестовые запросы
Top-3 Recall   = правильный товар среди первых 3 / все тестовые запросы
```

Отдельно тестируются:
- артикулы;
- неполные названия;
- разговорные формулировки;
- технические параметры;
- бренд + характеристика;
- запросы на замену;
- товары «нет в наличии».

### Аналоги

При подборе аналога проверяются **обязательные параметры**, а не только похожесть названия:

```text
Совместимый аналог =
напряжение ✓
номинальный ток ✓
тип/назначение ✓
ключевой стандарт или класс защиты ✓
бренд/серия — по приоритету пользователя
цена/наличие — актуальные
```

Если обязательный параметр неизвестен, ассистент не должен делать вид, что совместимость доказана: он должен запросить уточнение или передать сценарий менеджеру.

### Безопасность корзины

Критическая бизнес-метрика:

```text
Implicit request  → показать товар → запросить подтверждение
Explicit "Да"     → add_to_cart()
"No"/неуверенность → операция отменяется
```

Нарушение этого правила считается **критической ошибкой**, даже если выбран правильный товар.

## ⚙️ 9. Наблюдаемость и аналитика после запуска

После пилота ассистент может собирать обезличенные события:

| Event | Что сохраняем |
|---|---|
| `search_started` | текст запроса |
| `product_found` | product_id, позиция в выдаче |
| `alternative_shown` | исходный товар + предложенный аналог |
| `clarification_requested` | параметр, которого не хватило |
| `add_to_cart_confirmation_requested` | товар + цена на момент запроса |
| `add_to_cart_confirmed` | product_id |
| `add_to_cart_cancelled` | причина/тип отказа |
| `human_handoff` | причина передачи менеджеру |
| `purchase_completed` | факт покупки / order_id* |

\* Только при разрешённой интеграции с заказами и соблюдении требований к персональным данным.

На этих событиях можно построить воронку:

```text
Запрос
  ↓
Найден товар
  ↓
Открыта карточка
  ↓
Показан аналог / выбор
  ↓
Запрос подтверждения
  ↓
Добавление в корзину
  ↓
Оформление заказа
  ↓
Покупка
```

Это позволит видеть не только количество диалогов, но и **где именно AI создаёт или теряет конверсию**.

## 🎯 11. План проверки гипотезы на реальных данных

### Этап 1 — Baseline

Собрать за 2–4 недели:
- количество поисковых запросов;
- количество обращений к менеджерам;
- среднее время ответа;
- среднее время консультации;
- долю запросов «товара нет в наличии»;
- add-to-cart rate;
- conversion rate;
- причины отказа/возврата.

### Этап 2 — AI Pilot

Запустить ассистента на ограниченной доле трафика и сравнить с baseline.

### Этап 3 — A/B Test

Основные критерии:

```text
↑ conversion rate
↑ add-to-cart rate
↓ time-to-product
↓ human handoff
↓ среднее время консультации
↑ доля успешно подобранных аналогов
= 100% соблюдение подтверждения корзины
```

### Этап 4 — Business Impact

Финальная формула эффекта:

```text
Экономия на сервисе
= автоматизированные консультации × среднее время консультации × стоимость часа

Дополнительная выручка
= дополнительные заказы × средний чек × маржинальность

Общий эффект
= экономия на сервисе + дополнительная маржинальная прибыль
  − стоимость AI/API/инфраструктуры
```

## 🚧 12. Ограничения и риски

**1. Актуальность каталога.**  
AI не должен самостоятельно придумывать цену, остаток или характеристики. Эти данные должны приходить из источника каталога/API.

**2. Совместимость.**  
«Похожий товар» не равен «совместимый товар». Для критичных параметров нужен deterministic check.

**3. Ошибки LLM.**  
Для поиска и бизнес-операций используется Function Calling; модель не должна напрямую менять состояние корзины текстовой командой.

**4. Нагрузка и стоимость API.**  
После пилота необходимо считать стоимость одной AI-сессии:

```text
AI Cost / Session =
tokens + tool calls + embedding/search cost + инфраструктура
```

**5. Защита персональных данных.**  
В аналитике предпочтительно хранить минимально необходимый набор данных и не использовать персональные данные клиента без соответствующего основания.

## 🏆 13. Почему решение масштабируется

Архитектура отделяет **LLM-слой** от бизнес-логики:

```text
Пользователь
    ↓
AI / Intent Understanding
    ↓
Tools
 ┌───────────────┬────────────────┬─────────────────┐
 │ search        │ compare        │ add_to_cart     │
 └───────────────┴────────────────┴─────────────────┘
    ↓
EKT Catalog / API
```

Поэтому ту же схему можно расширять без переписывания всей системы:

- поиск по новым категориям;
- B2B-сценарии;
- подбор комплектов;
- расчёт потребности в материале;
- генерация спецификаций;
- передача сложного заказа менеджеру;
- аналитика клиентских запросов;
- рекомендации сопутствующих товаров.
